The case-safety chain

One case owns everything. Every child table carries case_id, so one query (where case_id = ?) pulls the full picture, and one delete wipes a case cleanly.

cases is the root. 1 case has many documents, events, actions and messages.
documents belong to one case. 1 document has many chunks and many facts.
chunks are the plain text pieces (with page number) that get copied into Cognee for search.
case_facts are exact extracted values (sum insured, bill amount). The maths reads only from here, never from Cognee.
evidence_items link a fact to the chunk that proves it. This is what the evidence drawer shows.

How the tables work together

1. Upload a document

  1. Insert documents row, status processing; file goes to Storage.
  2. Extract text per page, insert chunks.
  3. LLM extracts facts, insert case_facts with page and quote.
  4. Send chunks to Cognee, set synced_to_cognee = true.
  5. Rules update cases (coverage, gap, readiness).
  6. Insert case_events; set document status done.

2. Ask a question

  1. Save the user line in messages.
  2. Cognee returns matching text; match it back to a chunks row.
  3. Code checks the AI quote really sits inside that chunk text.
  4. Pass: insert evidence_items. Fail: set abstained = true.
  5. Save the assistant reply with evidence_json.

3. Readiness and reminder

  1. Read document_requirements for the case type.
  2. Add weight per passing document, partial_credit if uploaded but check fails.
  3. Policy 25 + bill 25 + admission 20 + unsigned discharge 8 = 78.
  4. Score under 100: insert an actions row, call n8n.
  5. n8n calls back; insert case_events "reminder_sent".

All tables

Rules the database enforces

Unique fact per document: UNIQUE (case_id, document_id, fact_key). Re-processing updates a fact, never duplicates it.
Status checks: processing_status, verification_status, actions.status, messages.role and readiness_score (0 to 100) all use CHECK constraints.
One readiness rule per document type: UNIQUE (case_type, document_type) on document_requirements.
updated_at trigger on cases so no client forgets to set it.
Row level security: a user may read or write a row only if its case belongs to them (cases.user_id = auth.uid()). Skip for the demo, add after.
Source of truth: amounts, readiness and status live only in Supabase. Cognee never writes to them.

Where each kind of data lives

Data Supabase Cognee
Original PDFs, images Storage No
Chunk text and page chunks Yes, embedded (rebuildable)
Embedding numbers No Yes, handled inside
Facts, amounts, readiness, status Yes Never
Chat and voice transcripts messages No, not evidence

Cognee datasets: financial_knowledge and policy_POL_889923 (pre-loaded), plus one per case, named in cases.cognee_dataset. If Cognee data is lost, re-send every chunk from chunks.

How rows end their lives

Cascade with the case: documents, chunks, case_facts, evidence_items, case_events, actions, messages.
Append-only by habit: case_events and messages are inserted, never edited.
Set null: if a document or chunk is deleted, facts and evidence keep their quote and page text.
Never deleted: document_requirements (seeded once).
